# Действия вне интерфейса

Редкие действия без экранов. Их выполняет технический ответственный по просьбе владельца.

## UC-OP1. Добавить или отключить администратора
- Экрана нет. Нужна строка в таблице администраторов БД с ролью «admin» или «super_admin».
- Строка в стартовом наборе данных переживает пересборку. Разовый SQL-запрос действует сразу.
- Команда — в `CLAUDE.md`, раздел «Как деплоить».
- Отключённый администратор не может войти. Уже открытая сессия живёт до истечения входа — до 6
  дней.

## UC-OP2. Восстановление доступа продавца при потере Telegram-аккаунта
Новый Telegram-аккаунт — это новый пользователь. Без процедуры он не видит старые чеки, баланс и
выплаты. Автоматического переноса нет: ни по имени, ни по номеру телефона.

1. **Обращение.** Продавец пишет в поддержку с нового аккаунта (Профиль → «Помощь»): ФИО, телефон из
   анкеты, примерная дата регистрации, точка.
2. **Проверка личности.** Номер телефона сам по себе доказательством не является.
3. **Решение** принимает super admin.
4. **Перенос** — запрос к API от имени super admin, с указанием нового аккаунта и основания (не
   короче 10 символов):
   - новый аккаунт входит как этот продавец: чеки, баланс и выплаты те же, данные не копируются;
   - старый аккаунт отключается сразу, в том числе уже открытая сессия: «Этот аккаунт Telegram
     отключён»;
   - уведомления бота приходят на новый аккаунт;
   - запись в журнал действий: старый и новый ID, кто сделал, основание.
5. **Отказ системы:**
   - у продавца есть заявка «новая» или «в обработке» — сначала выплатить или отклонить;
   - новый аккаунт — администратор;
   - новый аккаунт — уже другой продавец с данными.

   Пустую анкету, которую новый аккаунт создал простым открытием приложения, система удаляет
   сама.

Порядок действий для поддержки и открытые вопросы — [../procedures/ACCOUNT-RECOVERY.md](../procedures/ACCOUNT-RECOVERY.md).

## UC-OP3. Источники проверки чеков
- Смотреть список может любой админ — в «Пути чека».
- Включать, выключать и менять порядок может только super admin, через API. Каждое изменение
  пишется в журнал действий.
- Подключить proverkacheka: прописать токен в настройках сервера и перезапустить сервисы. Токен
  никогда не передаётся в чат и не коммитится.

## UC-OP4. Минимальная сумма выплаты
Настройка сервера, по умолчанию 3 000 ₽. Новое значение сразу видят продавцы (форма заявки) и
сервер. Меняется только с согласия владельца — значение зафиксировано в решении В-11.

## UC-OP5. Чек, выплаченный в окне выкатки
Ручной дозапуск разметки «Выплачен» — `ops/backfill_paid_out.sql`. Сначала пробный прогон без
изменений, потом применение. Только после резервной копии и с «да» владельца.

## UC-OP6. Очистка файлов старых чеков
Скрипт `cleanup_checked_receipts` заменяет файлы уже решённых старых чеков (одобренных и
отклонённых) на маленькие заглушки, чтобы освободить место. Без флага применения — только отчёт.
