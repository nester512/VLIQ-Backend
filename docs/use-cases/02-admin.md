# Mini App администратора

Общие правила — в [00-overview.md](00-overview.md).

- Вкладки: «Обзор», «Чеки» (проверка), «Выплаты», «Продавцы».
- Администратор и super admin видят **одинаковый** интерфейс.
- Требования: Telegram на смартфоне, Telegram ID внесён в список администраторов
  ([05-operations.md](05-operations.md)).

---

## UC-A1. Сводка («Обзор»)
Цифры считаются на сервере по всей базе. Каждая карточка ведёт в соответствующий список.

**Карточки:**
- «Продавцов» и «Активных» (с долей от базы).
- «Чеков загружено» — за всё время.
- «На проверке» — без чеков заблокированных продавцов.
- «Средний чек» — по одобренным, в целых рублях.
- «Выплачено» — количество заявок, оплаченных в этом месяце.

**Ещё на экране:**
- график «Чеки за 30 дней»;
- быстрые ссылки со счётчиками: «Проверить чеки», «Заявки на выплату», «Продавцы»;
- **«Топ продавцов»** — по начисленному за всё время (начисления с учётом корректировок), до 25
  человек. Сначала видно трёх, дальше «Показать всех». Нажатие открывает страницу продавца.

## UC-A2. Проверка чеков (колода)
Админ разбирает очередь карточками, как в приложении знакомств.

**Очередь:**
- только чеки «На проверке»;
- без чеков заблокированных продавцов;
- **сначала чеки без ФН/ФД/ФП** (временное правило от 2026-10-09), внутри группы — с самых старых;
- счётчик «N / всего».

**Карточка (без фото):**
- продавец (нажатие — его страница) и точка;
- сумма, бонус («не назначен»), дата покупки, дата загрузки, магазин, ФН·ФД·ФП;
- состав чека — до 3 позиций. Если состава нет — ссылка «открыть чек» на check.ofd.ru;
- метки: «Возможный дубль» / «Уникален», способ ввода (сканер, камера, фото, PDF, вручную), статус
  автопроверки, сигналы риска («Повтор чека», «Чек другого продавца», «Старше 30 дней», «Сумма ≠
  ОФД» и др.);
- «Подробнее» — полная карточка (UC-A3);
- ⓘ у заголовка — памятка «Как проверять чеки».

**Действия:**

| Действие | Жест / кнопка | Правила |
|---|---|---|
| Одобрить | вправо / «Одобрить» | Если бонус не назначен — спросит сумму (0,01–999 999 ₽). Продавцу уведомление |
| Отклонить | влево / «Отклонить» | Причина (минимум 3 символа, есть быстрые варианты). Продавцу уведомление с причиной |
| Пропустить | вниз / «Пропустить» | Чек уходит в конец колоды, на сервере ничего не меняется |

**Ещё:**
- Пропущенные чеки сохраняются, если уйти к продавцу и вернуться.
- Когда остались только пропущенные — экран «Основная очередь разобрана» и кнопка «К пропущенным».
- Пока одно действие выполняется, остальные заблокированы.
- Если чек уже решён другим админом, карточка возвращается и показывается сообщение.
- Одобрить чек заблокированного продавца нельзя.

## UC-A3. Карточка чека
Открывается из колоды, списка всех чеков, страницы продавца, заявки на выплату, дубля.

**Содержимое:**
- **Данные:** продавец, точка, даты, сумма, бонус, магазин, адрес, ФН/ФД/ФП. Ссылка «Проверить чек
  на check.ofd.ru».
- **Состав чека** — из ответа источника проверки.
- **Сигналы проверки.** Если чек совпадает с другим: «Совпадает с чеком #N: продавец · статус ·
  загружен · бонус» и кнопка «Открыть». «← Назад» возвращает к исходной карточке.
- **«Путь чека»** — UC-A4.
- **Причина отклонения**, если чек отклонён.
- У старых чеков, загруженных файлами, — их фото или PDF.

**Действия по статусу:**

| Статус | Доступно |
|---|---|
| На проверке | Одобрить, Отклонить, Изменить бонус |
| Одобрен | Отменить чек — списать бонус (причина обязательна), Изменить бонус (уменьшение — с причиной) |
| Выплачен | Отменить чек (причина; у продавца появится долг), Удалить чек (причина) |
| Отклонён | Удалить чек (причина) |
| Любой | Скопировать ФН/ФД/ФП, «К продавцу», Комментарий (до 2 000 символов), Заблокировать продавца |

**Ограничения:**
- Если чек входит в заявку на выплату со статусом «новая» или «в обработке», отменить, удалить или
  уменьшить бонус нельзя: «Чек входит в заявку на выплату #N — сначала выплатите или отклоните её».
- Удаление мягкое: чек скрывается из списков. Бонус, если был, списывается записью с причиной.

## UC-A4. Путь чека
Журнал всего, что происходило с чеком: кто, когда, через какой источник, с каким итогом.

**Сводка:**
- **Получен** — когда и каким способом.
- **Проверка** — кем подтверждён, или сколько было раундов и когда следующий. У старых чеков с
  файлами — «не нужна».
- **Решение** — кто и когда.

**События по порядку:**
- получен, проверен формат, отправлен на модерацию;
- раунд проверки, проверка у источника (раскрывается точный запрос и ответ);
- подтверждён / не подтверждён;
- одобрен / отклонён;
- бонус изменён, комментарий;
- включён в выплату, выплачен, выплата отменена;
- удалён.

События, восстановленные для старых чеков, помечены «восстановлено из истории».

**Кнопки:**
- «Проверить сейчас» — новый полный раунд;
- «у <источника>» — проверка у одного источника. Кнопка есть только у подключённых и включённых
  источников.

**Список источников** (только просмотр): порядок, название, состояние — основной, запасной,
выключен, не подключён, пауза.

## UC-A5. Все чеки
- Открывается с карточек сводки.
- Фильтры: «Все», «На проверке», «Одобрены», «Доработать», «Отклонены», «Выплачены». Фильтр
  сохраняется при возврате.
- Новые сверху, подгрузка при прокрутке, общее количество.
- В строке: магазин, продавец, время загрузки, кратко состав, статус, сумма.

## UC-A6. Продавцы
**Поиск** по имени, фамилии (любой порядок слов, регистр не важен), телефону, точке, городу или
Telegram ID.

**Фильтры:**
- статус — активные, ожидают, заблокированные;
- риск — низкий, средний, высокий;
- «Есть чеки на проверке».

**Сортировки:** новые, последняя активность, популярность (всего чеков), частота (чеков за 30
дней), риск.

**Список:**
- в строке: имя, точка и город (или «Анкета ещё не заполнена»), чеков всего и за 30 дней, статус,
  риск, сколько на проверке;
- подгрузка при прокрутке, итог «Найдено: N · показано M»;
- фильтры сохраняются при возврате.

**Риск** — подсказка, не правило. Считается по доле отклонённых чеков и доле дублей. Меньше 5
решений по продавцу — «мало данных».

## UC-A7. Страница продавца
- **Профиль:** Telegram ID, телефон, город, точка, дата регистрации, причина блокировки.
- **Деньги:** баланс, начислено всего, выплачено, на удержании (заявки в работе), средний бонус.
- **Активность:** чеков всего, одобрено, отклонено, на проверке, за 30 дней, первый и последний чек;
  график по неделям за 12 недель.
- **Фактор риска** — уровень, причины, сколько чеков с признаком дубля.
- **«Выплаты продавца»** — его заявки, все статусы, в том числе если он заблокирован.
- **История чеков** — все статусы с фильтром, в строке «Чек #ID», новые сверху. Фильтр сохраняется
  при возврате.

**Блокировка:**
- «Заблокировать» — причина необязательна. Продавцу приходит уведомление.
- «Разблокировать» — сразу, без подтверждения. Продавцу приходит уведомление.

## UC-A8. Выплаты
**Итоги** (по всем заявкам, не только загруженным):
- «К выплате» — сумма новых и взятых в работу, с количеством;
- «Выплачено в <месяц>» — сумма и количество.

**Список:**
- фильтры: «Все», «Новые», «В обработке», «Выплачены», «Отклонены»;
- сортировка: «Сначала новые» / «Сначала старые»;
- подгрузка при прокрутке, фильтры сохраняются;
- в строке: продавец, точка, способ, последние цифры номера, **дата создания** (и дата выплаты),
  статус, сумма;
- **заявки заблокированных продавцов** в работе в очередь и итоги не входят. Их видно отдельной
  меткой «Заблокированные продавцы: N — не в очереди». Выплаченные и отклонённые остаются в истории.

**Карточка заявки:**
- продавец (ссылка), точка, сумма, реквизиты полностью, статус;
- даты: создана, взята в работу, выплачена или отклонена; номер транзакции; причина отказа;
- **«Чеки в заявке»** — какие чеки покрыты и на какую сумму (частичное покрытие — «из X»).
  Нажатие открывает чек, «← Назад» возвращает к заявке.

**Действия** (только у «новой» и «в обработке»):

| Действие | Правила |
|---|---|
| «Взять в работу» | новая → в обработке |
| «Выплачено» | Номер транзакции — необязательно. Деньги списываются из резерва, полностью покрытые чеки становятся «Выплачен», продавцу уведомление. Можно и без «Взять в работу» |
| «Отклонить» | Причина обязательна. Деньги возвращаются на баланс продавца, продавцу уведомление с причиной |

**Ограничения:**
- У заблокированного продавца доступно только «Отклонить». Выплатить нельзя.
- Выплату админ делает сам, вне системы. Система только фиксирует факт.

## Переходы между экранами
- Из любой сущности — один тап до связанной: чек → продавец, заявка → продавец и чеки, дубль →
  исходный чек, продавец → его выплаты, топ → продавец.
- «Назад» возвращает туда, откуда пришёл, с теми же фильтрами.
- Карточки, открытые одна из другой, закрываются по очереди: «← Назад». Закрытие закрывает все.

## Расхождения (известно на 2026-10-09)
- Фильтры «Доработать» и «На доработке» есть в списках, но статус «на доработке» в продукте не
  используется: перевести чек в него нельзя. Отключённое действие «на доработку» на сервере на
  деле отклоняет чек.
- Причину отклонения чека в статусе «на проверке» требует только экран, сервер её не требует.
- «Заблокировать пользователя» в карточке чека показывается и уже заблокированному продавцу
  (сервер отвечает отказом).
- Изменение суммы заявки на выплату есть только в API: проверяет минимум и блокировку, пересчитывает
  чеки, уведомляет продавца. Экрана нет.
- Комментарии к чеку сохраняются, но видны только как событие в «Пути чека».
- Журнал действий админов (audit log) пишется, но экрана для него нет.
- Карточка «Выплачено» на сводке показывает количество заявок, а не сумму.
