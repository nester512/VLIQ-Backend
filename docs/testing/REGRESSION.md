# Регресс перед выкаткой develop → main (2026-10-09…13)

Объём: всё, что есть в `develop` и нет в `main` (72 коммита на 2026-10-13): QR-приём, путь чека, выплаты,
админка (продавцы, очередь, переходы), восстановление доступа, мониторинг, обновление стека.
Стенд: `https://test-nekuro.online` (бот стенда). Данные — только синтетические (стендовые
продавцы 7000xxxx, QR-набор `docs/testing/qr-kit/`).

**Колонка «Как»:** `API` — автоматически (`ops/regression/stage_regression.py`, внутри контейнера
стенда), `UI` — руками с телефона (два аккаунта, `docs/testing/MANUAL-QA.md`), `CI` — юнит/PG-тесты.
Тикет — ключ Jira там, где он известен (KAN-3, KAN-38, KAN-39, KAN-50); остальные задачи — по названию.
`UI-авто` — экраны на стенде в браузере Telegram-эмулятора (`ops/regression/ui/`).

**Полный регресс — команды (из корня репо):**
1. Бэкенд, юнит: `vliq-backend-dev314` → `python -m pytest --ignore=tests/integration --ignore=tests/migrations -q`
2. Бэкенд, настоящая БД и миграции: `tests/integration tests/migrations` с `TEST_PG_URL` (см. `CLAUDE.md`)
3. Фронтенд: `npx tsc -b && npx eslint src && npx vitest run && npx vite build`
4. API на стенде: `docker exec -i vliq-backend python - < ops/regression/stage_regression.py` → `SUMMARY … fail=0`
5. Распознавание QR на наборе чеков: `sh ops/regression/qr/run.sh <папка набора с regression.csv>` → `QR_REGRESSION … smoke_fail=0`
   (тот же код, что у продавца на «Фото или PDF чека»; выводит только счётчики; синтетический набор — `docs/testing/qr-kit`;
   набор из настоящих чеков — только там, где его хранение и обработка разрешены).
6. Экраны и «назад» на стенде: `sh ops/regression/ui/run.sh` → `LAYOUT issues=0`, `BACK fails=0`
   (оба роля, 344 и 412 px, тёмная и светлая тема; обрезанный текст, наложения, выход за край, сырые
   коды на экране, ошибки JS/HTTP; синтетические аккаунты стенда, на проде не запускается).

> Браузерные спеки `frontend/e2e/` в CI **не запускаются** — шаг 5 их заменяет, пока не заведена
> CI-джоба с Playwright.
