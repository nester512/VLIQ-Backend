# Ручная проверка на стенде — два аккаунта (продавец + админ)

Стенд: бот стенда → Mini App `https://test-nekuro.online`. Источник проверки на стенде — **заглушка**
(`CHECK_PROVIDER_STUB=true`, в «Пути чека» — «заглушка (стенд)»), её поведение задано правилами
(ниже), чтобы проверить все ветки. ФНС / proverkacheka / Платформа ОФД / Такском видны в списке источников
как «не подключён» — адаптеров к ним ещё нет. На проде заглушка не включается никогда.

Аккаунт **А — продавец** (зарегистрирован, статус «активен»), аккаунт **Б — админ**
(добавить в `vliq.admin` — `docs/CI-CD.md` → «Админ на стенде»).

## Набор QR — `docs/testing/qr-kit/`
Синтетические чеки (дата — 2026-10-09, годятся до ~8 ноября). Сканировать телефоном прямо с экрана
или загружать как «Фото или PDF чека».

|---|---|

| `02-ofd-found-on-3rd-attempt.png` | «Проверка: повтор по расписанию»; подтверждается на 3-м раунде (cron через ~5 и ~15 мин или 2× «Проверить сейчас») |
| `03-ofd-never-found.png` | Повторы по расписанию, админ видит «нет данных»; модерация вручную доступна |

| `10-e-receipt-qr-on-page-3.pdf` | Как PDF: QR только на 3-й странице — распознаётся (сканируются все страницы) |

Правила заглушки: ФН на `9999…` — никогда не находится; ФП на `…0` — находится с 3-й попытки;
остальное — сразу. Повторная отправка того же файла → предупреждение «уже отправляли», у админа —
сигнал дубля (не блок).

## А — продавец
1. «Добавить чек» → **Сканировать QR-код** (телефон): `01` → карточка «Проверьте данные чека» →
   без галочки кнопка неактивна → галочка → «Отправить» → экран статуса.
2. Сканировать `05`, затем `04` → сообщения с причиной, сканер не закрывается, запросов нет.
3. **Фото или PDF чека**: `08` (jpg), `07` (два чека → выбор), `09` (PDF).
4. **Ввести вручную**: пустая форма → «Заполните поле» ×6; ФН из 15 цифр → «ФН — ровно 16 цифр»;
   исправить → подтверждение → отправить. Enter в форме = «Проверить».
5. Повторно отправить `01` → «Вы уже отправляли этот чек с этого телефона» + кнопка «Отправить повторно».
6. Telegram Desktop: кнопки сканера Telegram нет, остаются «Фото или PDF» и «Ввести вручную».
7. Старый iPhone / Android: страница открывается, камера/фото работают (wasm-распознавание).

## Б — админ
1. **Проверка чеков**: карточка без фото — сумма, бонус, дата, магазин, ФН·ФД·ФП, источник, статус проверки («Подтверждён · <кем>»), метки риска; «Подробнее»/тап — фото и всё остальное; ⓘ у заголовка — все пояснения; на узком экране (Flip) кнопки не наезжают. «Пропустить» и свайп вниз → чек уходит в конец колоды; «пропущено N» в
   заголовке; одобрить/отклонить следующие; пропущенный возвращается.
2. Карточка чека → панель **Путь чека** (один журнал на чек, его видит только админ; продавец — только статус):
   - сводка: **Получен** (когда, откуда) · **Проверка** (кем подтверждён и когда / раундов N, следующий —
     когда) · **Решение** (кто и когда);
   - список источников по порядку: 10 ФНС → 20 proverkacheka (основные) → 30 Платформа ОФД → 40 Такском
     (запасные); на стенде подключена только заглушка;
   - шаги по порядку: чек получен (продавец, источник) → данные проверены → передан на модерацию →
     раунд проверки → проверка у источника (тап — точный запрос, разобранный ответ и сырой ответ,
     версия адаптера) → подтверждён / раунд без подтверждения → одобрен (бонус) …;
   - для `02`: «Проверить сейчас» (полный раунд) или «у заглушка (стенд)» (только у этого источника) →
     после 2 нажатий «Подтверждён · заглушка (стенд)», в журнале — триггер «вручную»;
   - для старых чеков (до этой версии) шаги восстановлены из истории и помечены «восстановлено»;
   - бонус изменён / комментарий / отклонение с причиной — тоже появляются в пути.
3. Тап по имени продавца в карточке / «К продавцу» → страница продавца (статистика, риск, история).
4. **Продавцы**: поиск, фильтры статус/риск/«на проверке», 5 сортировок, бесконечный скролл (2000+),
   «назад» со страницы продавца сохраняет фильтры.
5. После одобрения/отклонения: счётчики в списке продавцов, архиве «Все чеки» и на главной
   обновились без перезагрузки.
6. **Главная**: цифры сводки; «Чеки за 30 дней».
7. Заблокировать продавца А со страницы продавца → у А приходит уведомление в Telegram, загрузка
   чека блокируется; разблокировать.

## В — выплаты (А + Б), `docs/design/PAYOUTS.md`
1. **А, «Баланс»**: «На проверке» — сумма бонусов по нерешённым чекам (под ней — сколько чеков);
   «Всего выплачено» — «ещё N ₽ в заявках», если есть заявки в работе.
2. **Б**: одобрите пару чеков А с бонусом (в сумме ≥ 3 000 ₽).
3. **А, «Запросить выплату»**: меньше 3 000 ₽ — кнопка неактивна; городской номер (+7 495 …) —
   «Номер мобильного…»; верная заявка → в «Мои заявки» статус «Новая»; на балансе доступно уменьшилось,
   «в заявках» — сумма. Двойной тап по «Запросить» — заявка одна.
4. **Б, «Выплаты»**: итоги «К выплате» / «Выплачено в …» считаются по всем заявкам. Заявка → блок
   «Чеки в заявке» (с самых старых, последний может быть частично). «Взять в работу» → «В обработке».
5. **Б**: пока заявка в работе, откройте покрытый ею чек → «Отменить чек — списать бонус» →
   ответ «Чек входит в заявку на выплату #N…» — ничего не списано.
6. **Б, «Отклонить»**: без причины нельзя; с причиной → у А уведомление с причиной, в «Мои заявки» —
   «Отклонена» + причина; деньги снова доступны; у чеков в «Пути чека» — «Заявка на выплату отклонена».
7. **А**: новая заявка. **Б**: номер транзакции → «Выплачено» → у А «Выплата отправлена» (одно
   сообщение, даже при повторном нажатии); полностью покрытые чеки — «Выплачен», в «Пути чека» —
   «Включён в заявку…» → «Выплачен»; частично покрытый остаётся «Одобрен» («частично»).
8. **Б**: выплаченный чек → «Отменить чек — списать бонус» → обязательна причина; у А доступно уходит в
   минус (долг), новую заявку создать нельзя. «Удалить чек» тоже просит причину.
9. **Б**: «Изменить бонус» у одобренного чека — увеличение сразу, уменьшение — с причиной.

## Инфраструктура (уже проверено автоматически, для справки)
- Стенд на Python 3.14 / Node 26; миграции `0010` (индексы), `0011` (путь чека + бэкфилл истории) и `0012`
  (выплаты: покрытие чеков старых заявок) применены.
- Перед миграцией деплой снял бэкап БД: `/srv/vliq-stage/.deploy/backups/*.dump`.
