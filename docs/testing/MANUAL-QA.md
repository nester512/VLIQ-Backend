# Ручная проверка на стенде — два аккаунта (продавец + админ)

Стенд: бот стенда → Mini App `https://test-nekuro.online`. ОФД на стенде — **заглушка**
(`OFD_PROVIDER=fake`), её поведение задано правилами (ниже), чтобы проверить все ветки.

Аккаунт **А — продавец** (зарегистрирован, статус «активен»), аккаунт **Б — админ**
(добавить в `vliq.admin` — `docs/CI-CD.md` → «Админ на стенде»).

## Набор QR — `docs/testing/qr-kit/`
Синтетические чеки (дата — 2026-10-09, годятся до ~8 ноября). Сканировать телефоном прямо с экрана
или загружать как «Фото или PDF чека».

| Файл | Что должно произойти |
|---|---|
| `01-ok-verified-at-once.png` | Принят → у админа «Подтверждён в ОФД» сразу (1 попытка, «при загрузке») |
| `02-ofd-found-on-3rd-attempt.png` | «ОФД: повтор по расписанию»; найден на 3-й попытке (cron через ~5 и ~15 мин или 2× «Проверить сейчас») |
| `03-ofd-never-found.png` | Повторы по расписанию, админ видит «нет данных»; модерация вручную доступна |
| `04-refund-rejected-on-phone.png` | **Не отправляется**: «Это не чек продажи (возврат или коррекция)» |
| `05-not-a-receipt.png` | **Не отправляется**: «Это не QR-код кассового чека»; сканер Telegram остаётся открытым |
| `06-older-than-30-days-warning.png` | Принимается с предупреждением «Чеку больше 30 дней…» |
| `07-two-receipts-on-one-photo.png` | Как фото: «На снимке несколько чеков» → выбрать один |
| `08-photo-of-receipt-rotated.jpg` | Как фото: повёрнутый снимок распознаётся |
| `09-e-receipt.pdf` | Как PDF: распознаётся; источник «PDF» |

Правила заглушки ОФД: ФН на `9999…` — никогда не находится; ФП на `…0` — находится с 3-й попытки;
остальное — сразу. Повторная отправка того же файла → предупреждение «уже отправляли», у админа —
сигнал дубля (не блок).

## А — продавец
1. «Добавить чек» → **Сканировать QR-код** (телефон): `01` → карточка «Проверьте данные чека» →
   без галочки кнопка неактивна → галочка → «Отправить» → экран статуса.
2. Сканировать `05`, затем `04` → сообщения с причиной, сканер не закрывается, запросов нет.
3. **Фото или PDF чека**: `08` (jpg), `07` (два чека → выбор), `09` (PDF).
4. **Ввести вручную**: пустая форма → «Заполните поле» ×6; ФН из 15 цифр → «ФН — ровно 16 цифр»;
   исправить → подтверждение → отправить. Enter в форме = «Проверить».
5. Повторно отправить `01` → «Вы уже отправляли этот чек с этого телефона» + кнопка «Отправить повторно».
6. Telegram Desktop: кнопки сканера Telegram нет, остаются «Фото или PDF» и «Ввести вручную».
7. Старый iPhone / Android: страница открывается, камера/фото работают (wasm-распознавание).

## Б — админ
1. **Проверка чеков**: «Пропустить» и свайп вниз → чек уходит в конец колоды; «пропущено N» в
   заголовке; одобрить/отклонить следующие; пропущенный возвращается.
2. Карточка чека: значки «QR · сканер Telegram» / «Ручной ввод данных» и статус ОФД; панель
   **Проверка в ОФД** — попытки (при загрузке / по расписанию / вручную), раскрыть запрос/ответ,
   «Проверить сейчас» для `02` → после 2 нажатий «Подтверждён в ОФД».
3. Тап по имени продавца в карточке / «К продавцу» → страница продавца (статистика, риск, история).
4. **Продавцы**: поиск, фильтры статус/риск/«на проверке», 5 сортировок, бесконечный скролл (2000+),
   «назад» со страницы продавца сохраняет фильтры.
5. После одобрения/отклонения: счётчики в списке продавцов, архиве «Все чеки» и на главной
   обновились без перезагрузки.
6. **Главная**: цифры сводки; «Чеки за 30 дней».
7. Заблокировать продавца А со страницы продавца → у А приходит уведомление в Telegram, загрузка
   чека блокируется; разблокировать.
