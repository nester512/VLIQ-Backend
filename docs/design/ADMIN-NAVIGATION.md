# Админка: переходы между сущностями (KAN-3), 2026-10-09

## Что говорит UC
`docs/VLIQ PRD+BRD/Use cases VLIQ.md` правил навигации не задаёт. Требования, из которых они следуют:
- **A2** — в карточке проверки видно продавца; последняя страница карточки — информация о чеке и
  продавце (админ должен понять, кто это и что он присылал раньше);
- **A3** — админ видит, какие чеки покрыты выплатой (В-8-A);
- **A1** — блокировка продавца со страницы продавца.

Отсюда правило: **из любой сущности — один тап до связанной, и «назад» возвращает туда, откуда пришёл,
с теми же фильтрами.**

## Карта переходов (после KAN-3)
| Откуда | Куда | Как |
|---|---|---|
| Колода проверки (карточка) | Продавец | имя продавца на карточке |
| Карточка чека | Продавец | «К продавцу», имя продавца |
| Карточка чека (дубль) | Исходный чек | «Совпадает с чеком #N · Открыть» → «← Назад» к дублю |
| Список продавцов / Топ продавцов | Продавец | строка |
| Продавец | Чек | строка истории → карточка чека |
| Продавец | Выплаты продавца | «Выплаты продавца» → `/admin/payouts?seller=<id>` (вся история, вкл. заблокированного) |
| Все чеки | Чек → продавец | строка → карточка → «К продавцу» |
| Заявка на выплату | Продавец | имя продавца (ссылка) |
| Заявка на выплату | Чек | «Чеки в заявке» → карточка чека → «← Назад» к заявке |

## «Назад»
- Между страницами — история браузера/Telegram BackButton; фильтры в URL: продавцы, все чеки,
  выплаты (статус, сортировка, продавец, «заблокированные»), **история чеков продавца** (`?status=`, было
  в состоянии и терялось).
- Между карточками (bottom sheet) — **стек**: карточка, открытая из карточки, показывает «← Назад»;
  закрытие закрывает всё.
- Колода проверки: пропущенные чеки **сохраняются** при уходе к продавцу и возврате (sessionStorage на
  вкладку); решённые уходят из очереди на сервере.
