# Выплаты — деньги, заявки, чеки (дизайн, 2026-10-09)

Источник требований: `docs/VLIQ PRD+BRD/Use cases VLIQ.md` — S4 (баланс), S5 (заявка),
A3 (выплаты), решения В-5, В-8. Решения владельца по ревизии 2026-10-09 — внизу.

## Деньги: одна книга, только добавление
`bonus_transaction` — журнал денег продавца (знак = направление). Строки не правятся и не
удаляются; любое изменение суммы — **новая строка с причиной** (`reason`).

| kind | когда | сумма |
|---|---|---|
| `accrual_receipt` | одобрение чека | +бонус |
| `correction` | правка бонуса / отмена одобренного или выплаченного чека | ±разница, **причина обязательна** |
| `payout_hold` | заявка создана (и правка суммы заявки) | −сумма |
| `payout_completed` | заявка выплачена | −сумма (информационно, баланс не трогает) |
| `payout_reverted` | заявка отклонена | +сумма |

Баланс (`seller/services/balance_service.py`):
- **доступно** = начисления + коррекции + возвраты заявок − резервы (`payout_hold`);
- **в резерве** = сумма заявок в статусах «новая / в обработке» (раньше считалось по
  `payout_hold` и не уменьшалось после выплаты/отказа — баг);
- **всего начислено** = начисления + коррекции; **всего выплачено** = |`payout_completed`|;
- **на проверке** = сумма бонусов чеков, ещё не решённых админом (S4: «суммы»).

Доступно может стать **отрицательным** только одним способом: админ отменил уже выплаченный чек
(с причиной) — это долг продавца, он гасится следующими начислениями; новую заявку при этом
создать нельзя.

## Заявка на выплату
Статусы: `new` → `in_progress` («взята в работу») → `paid` | `rejected`.
Отметки времени: `taken_at`, `paid_at`, `rejected_at` (аналитика «выплачено за месяц» — по `paid_at`).

Создание (продавец, одна транзакция, строка продавца под `FOR UPDATE`):
1. Проверки: продавец `active`; способ — только СБП по телефону, номер нормализуется в
   `+7XXXXXXXXXX`; сумма ≥ минимума (`PAYOUT_MIN_AMOUNT`, 3 000 ₽) и ≤ доступно.
2. Защита от дублей — на уровне БД: `UNIQUE (seller_id, idempotency_key)`. Повтор с тем же
   ключом возвращает ту же заявку; фронт держит один ключ на одну отправку формы.
3. `payout_request(new)` + `payout_hold −N`.
4. **Покрытие чеков (В-8-A):** сумма раскладывается по одобренным чекам продавца **с самых старых**
   (FIFO) → строки `payout_receipt (payout_id, receipt_id, amount)`; частичное покрытие чека
   возможно. В «Путь чека» — `included_in_payout`.
5. `audit_log(create_payout)`.

Взять в работу (админ): `new → in_progress`, `taken_at`, audit.

Выплачено (админ, номер транзакции — опционально):
`paid`, `paid_at`, `payout_completed −N`; каждый чек, покрытый оплаченными заявками полностью,
`approved → paid_out` + событие `paid_out` (частично покрытый — событие с `partial`);
уведомление «Выплата отправлена» — **в той же транзакции** (outbox), повторное нажатие не шлёт второе.

Отклонить (админ, **причина обязательна**): `rejected`, `rejected_at`, `payout_reverted +N`;
у чеков событие `payout_reverted` (покрытие освобождается — строки связи остаются как история,
в расчёт идут только заявки не в `rejected`); продавцу уведомление с причиной; причина видна
в «Мои заявки».

Правка суммы (админ, только `new/in_progress`): дельта `payout_hold`, покрытие пересчитывается.

## Чек после одобрения — транзитивные зависимости
- Отклонить одобренный / **выплаченный** чек, удалить его, уменьшить бонус — только с
  **причиной** → `correction` с этой причиной + событие в «Пути чека».
- Чек, покрытый заявкой в работе (`new/in_progress`), менять нельзя (409
  `RECEIPT_IN_ACTIVE_PAYOUT`): сначала решить заявку.
- Общий `PATCH /receipts/{id}` больше не меняет статус, бонус и удаление — только через
  действия выше (иначе деньги расходятся с книгой).

## Наследие (прод)
Миграция `0012` только добавляет: колонки заявки, `payout_receipt`, уникальный индекс
(`CONCURRENTLY`). Для уже существующих заявок покрытие восстанавливается тем же FIFO (вставка в
новую таблицу, идемпотентно).

**«Выплачен» у старых чеков ставит миграция `0014` при выкатке** (решение владельца 2026-10-09):
каждый одобренный чек, полностью покрытый ВЫПЛАЧЕННЫМИ заявками, → `paid_out` + событие пути
`paid_out` (`backfilled`, `migration: 0014`). Деньги не трогаются; повторный запуск ничего не меняет;
откат возвращает «Одобрен» ровно этим чекам. `ops/backfill_paid_out.sql` — дозапуск вручную
(например, для заявки, выплаченной в окне между миграцией и стартом нового кода).

## Решения владельца (2026-10-09)
Резерв — чинить; связь заявки с чеками — обязательно; дубли — убрать, ужесточить валидацию;
уход в минус — транзакцией с причиной; уведомление — атомарно; audit, «в обработке», уведомление
об отказе — да (уведомления админам — позже); реквизиты — как есть; минимум 3 000 ₽ — зафиксировать
в BRD; «на проверке» — сумма; причина отказа видна продавцу; итоги у админа — на сервере;
номер транзакции и причина отказа — в интерфейсе админа.
