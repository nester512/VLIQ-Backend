# Восстановление доступа при потере Telegram-аккаунта

Продавец входит по Telegram ID. Смена username на вход не влияет. Новый Telegram-аккаунт — это новый
ID: без процедуры он не видит старые чеки, баланс и выплаты. **Автоматического переноса нет** — ни по
имени, ни по номеру телефона; сам продавец ничего привязать не может.

## Flow
1. **Обращение** — продавец пишет в поддержку с НОВОГО аккаунта (Профиль → «Помощь»): ФИО, телефон из
   анкеты, примерная дата регистрации, точка.
2. **Проверка личности** (оператор поддержки) — *предложение, нужно согласовать владельцу*:
   - звонок на номер из анкеты (номер должен совпасть) **и** одно из:
     - видеозвонок / фото с документом, ФИО совпадает с анкетой;
     - подтверждение от руководителя точки / сети;
     - детали, известные только продавцу: суммы и даты последних выплат, номер последнего чека.
   - Номер телефона сам по себе — **не** доказательство (его могут переоформить).
3. **Решение** — *предложение*: super_admin (владелец доступа к БД / ответственный за выплаты). Отказ —
   с причиной в ответе продавцу.
4. **Перенос** (super_admin, админ-API):
   `POST /api/v1/sellers/{старый telegram_id}/transfer-login` `{ "new_telegram_id": …, "reason": "кто и как проверил" }`
   - данные продавца **не переносятся** — новый аккаунт входит как этот продавец (чеки, баланс,
     история выплат — те же); потерянный аккаунт отключается («Этот аккаунт Telegram отключён…»);
   - уведомления бота приходят на новый аккаунт;
   - **отказ**, если: у продавца заявка на выплату в работе (сначала выплатить / отклонить); новый аккаунт
     уже зарегистрирован как продавец, занят другим продавцом или админом (ручной разбор); основание
     короче 10 символов;
   - если новый аккаунт только открыл приложение (пустая анкета без чеков и денег) — эта пустышка
     удаляется автоматически;
   - повторный запрос — без изменений (`already_linked: true`).
5. **Аудит** — `audit_log.action = transfer_seller_login`: старый и новый Telegram ID, исполнитель,
   дата, основание.
