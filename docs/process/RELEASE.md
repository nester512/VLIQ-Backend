# Как изменения попадают к продавцам

Правило владельца: **ни одна строка данных не теряется и не искажается**, а каждое изменение проверено
до того, как его увидят живые продавцы.

## Два стенда
| | Тестовый стенд | Прод |
|---|---|---|
| Для чего | проверять изменения | работают живые продавцы |
| Адрес | test-nekuro.online, свой тестовый бот | shamilara.fun, рабочий бот |
| Данные | только тестовые (придуманные продавцы и чеки) | настоящие |
| Когда обновляется | сразу после каждого изменения | только по решению владельца, ночью |

Настоящие данные с прода на тестовый стенд не копируются.

## Путь одного изменения
1. **Задача** — ошибка или улучшение.
2. **Сделано и описано.** Поведение записано в документы продукта (`use-cases`), к нему есть автоматическая
   проверка, которая ловит именно эту ошибку, и пункт в списке регресса.
3. **Тестовый стенд** — изменение появляется там автоматически, если все автоматические проверки зелёные.

## Перед выпуском на прод
| Шаг | Что проверяем | Кто | Итог |
|---|---|---|---|
| 1. Регресс | все функции по списку: чеки, проверка, выплаты, продавцы, блокировка, восстановление доступа; все экраны обеих ролей на узком и обычном телефоне; кнопка «назад» | разработчик | все проверки зелёные |
| 2. Обкатка на наборе чеков | приём и распознавание чеков на большом наборе: фото, скриншоты, PDF, плохие снимки, особые случаи (возврат, чек в будущем, старый чек, два чека на снимке) | разработчик | доля распознанных чеков не хуже прежней, особые случаи обработаны правильно |
| 3. Проверка через бота | вручную на телефоне через тестового бота, два аккаунта — продавец и админ: отправить чек, проверить, одобрить, запросить выплату, выплатить, отклонить, заблокировать | тестировщик или владелец | сценарии проходят, уведомления приходят |
| 4. Решение | всё выше пройдено | владелец | «да» на выпуск |
| 5. Репетиция переезда (ночь 1) | на сервере прода, на копии данных: обновление проходит, данные до и после совпадают, откат возвращает всё как было | специалист по серверу | итог «PASS» |
| 6. Переезд (ночь 2) | выпуск на прод: резервная копия → обновление → проверки | специалист по серверу, владелец подтверждает кнопкой | прод работает, проверки после выпуска пройдены |
| 7. Наблюдение | первые часы после выпуска: ошибки, недоставленные уведомления, обращения продавцов | разработчик | замечаний нет |

**Набор чеков для обкатки:**
- на тестовом стенде — только придуманные чеки и чеки команды, отданные с согласия;
- набор из настоящих чеков прода используется только на сервере прода и никуда не копируется.

## Почему ночью и почему две ночи
- Ночью меньше всего продавцов в приложении.
- Первая ночь — репетиция на копии: если что-то не так, живая база не тронута, есть время исправить.
- Вторая ночь — сам выпуск, уже проверенный на тех же данных.

## Если что-то пошло не так
- **Новая версия не запустилась** — автоматически возвращается прежняя, данные не трогаются.
- **Ошибка в работе** — специалист возвращает прежнюю версию программы, данные остаются как есть.
- **Испорчены данные** — только с «да» владельца: восстановление из резервной копии, сделанной перед
  выпуском. Всё, что сделали после копии, при этом потеряется, поэтому сначала ищем точечное исправление.

## Защита данных прода — постоянно
- Резервная копия перед каждым обновлением и каждую ночь; копия хранится и вне сервера.
- Данные прода нельзя удалить случайной командой; без них прод не запустится пустым.
- Ручные изменения данных на проде — только после резервной копии и с «да» владельца.
- Выпуск на прод — только после нажатия «подтвердить» владельцем.
