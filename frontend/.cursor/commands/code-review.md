# /code-review

Локальный обзор изменений перед merge или после доработки. Без внешних API по умолчанию — только репозиторий и при наличии `gh` для GitHub.

**Аргумент (опционально):** фокус — `staged`, `uncommitted`, или номер PR для `gh` (если установлен и репо на github.com).

## По умолчанию (без gh или без PR)

1. `git fetch origin` (если есть `origin`).
2. Определи `BASE` как в `/push` (`main` или `master`).
3. Покажи дифф относительно базы (устойчиво к истории):
   ```bash
   MB=$(git merge-base HEAD "origin/$BASE")
   git diff "$MB"...HEAD
   ```
4. Проверь по чеклисту:
   - корректность и краевые случаи;
   - безопасность (инъекции, секреты, XSS для UI);
   - соответствие `.cursor/rules/*.mdc` для затронутых типов файлов;
   - тесты: что должно было добавиться/обновиться;
   - нет лишних файлов (логи, `.env`, артефакты сборки).
5. При необходимости предложи запустить субагента **code-reviewer** из `.cursor/agents/code-reviewer.md` с узким контекстом.

## Если доступен `gh` и нужен PR

1. `gh pr view` / `gh pr diff` для текущей ветки.
2. Тот же чеклист + комментарии ревьюеров на PR (если есть).

## Формат ответа

- Краткое резюме изменений.
- Список находок: **блокер** / **важно** / **желательно** с путями к файлам.
- Явно: «готово к merge» или «нужны правки: …».
