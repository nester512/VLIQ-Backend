# /respond-to-review

Отработать замечания код-ревью: только git, правки в репо и при наличии GitHub CLI.

## 1. Собрать список замечаний

**Вариант A — пользователь вставил список в чат**  
Используй его как единственный источник.

**Вариант B — GitHub (`gh`)**  
```bash
gh pr view --json reviews,comments 2>/dev/null
gh pr diff
```
Вытяни открытые треды и inline-комментарии; если PR нет — остановись и попроси ссылку или вставку текста ревью.

## 2. Для каждого пункта

- Прочитай указанный файл и контекст.
- Реши: согласен (исправить), частично, или обоснованный отказ (редко).
- Внеси правки минимально необходимым диффом.

## 3. Проверки

- Линтер и тесты для затронутых пакетов (как в `AGENTS.md`).
- Не используй `--no-verify` без явного запроса.

## 4. Коммит

Один или несколько логичных коммитов с понятными сообщениями; без force-push без согласия пользователя.

## 5. Итог для пользователя

Таблица: замечание → что сделано (файлы). Если что-то не исправлено — причина и что нужно от пользователя/ревьюера.

## Не делать

- Не обращайся к закрытым API, локальным базам ревью или токенам без явного запроса пользователя.
